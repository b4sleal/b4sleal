### 🚀 Featured Project · GoldenGuide
<a href="https://askgoldenguide.ca"><img src="./GoldenGuideLogo.png" height="28" alt="GoldenGuide" align="absmiddle"></a>
**[GoldenGuide](https://github.com/b4sleal/GoldenGuide)** · [Live Application](https://askgoldenguide.ca)
A full-stack AI academic advising platform that makes university course information and academic resources easier to access. It gives **source-linked answers** through a streaming React interface, backed by a system built for scalability, reliability, and maintainability.
| Engineering Area | Implementation |
|:---|:---|
| 🧠 **AI & Retrieval** | Multi-stage RAG pipeline; structured PostgreSQL lookups; Qdrant hybrid retrieval using dense, sparse, and ColBERT vectors; cross-encoder reranking; streaming responses with source citations |
| 🎯 **Accuracy & Reliability** | Deterministic course-code and academic-term extraction; explicit handling of missing, failed, and incomplete retrieval; source recall benchmarks; retrieval evaluation before and after reranking |
| 💬 **Frontend & Streaming UI** | React 19 and strict TypeScript single-page app built with Vite; NDJSON answer streaming with a pure, unit-tested answer state machine (pending, streaming, complete, error, interrupted, stopped); stop and retry controls; inline citation chips; safe Markdown rendering; evidence tables rendered from structured data |
| 🔗 **Type-Safe API Contract** | TypeScript client generated from FastAPI's OpenAPI schema, so backend contract changes fail the type check before deployment; runtime Zod validation of every stream event; forward-compatible handling of unknown events; structured error envelopes with request and trace IDs |
| 🧭 **User Experience** | Persistent conversation history with follow-up context; TanStack Router and Query; live status messages while sources are searched; light and dark themes; responsive sidebar and mobile drawer; accessible Radix/shadcn components; keyboard navigation and screen-reader announcements |
| 🏗️ **Backend Architecture** | Python 3.14; FastAPI; hexagonal architecture; domain-driven design principles; dependency injection; configurable provider registries; interchangeable LLM, embedding, database, storage, caching, and authentication implementations |
| 📚 **Data Engineering** | Automated crawling of WLU Academic Calendar and university webpages; HTML/PDF extraction; data normalization; recursive document chunking; embedding generation; vector indexing; nightly re-ingestion |
| ⚙️ **Background Processing** | Fault-tolerant job execution; database-backed distributed locking; job heartbeats; interrupted-job recovery; scheduled workflows; independent CPU/GPU embedding service |
| 🌐 **Distributed Infrastructure** | Docker Compose; multi-machine service deployment; private Tailscale networking; Nginx-served static frontend with API proxying and immutable asset caching; independently deployable frontend, backend, database, vector storage, object storage, and embedding workloads |
| 🚀 **Deployment & Environments** | Development, staging, and production configurations; Vite hot-reload development proxy; environment isolation; HTTPS deployment through Cloudflare Tunnel; public application at [askgoldenguide.ca](https://askgoldenguide.ca); secure production startup validation |
| 🔐 **Security & Authentication** | Provider-independent OIDC authentication; Keycloak development identity provider; Redis-backed sessions; same-origin cookie and request checks; strict Content Security Policy; role-based authorization; fail-closed access controls; hashed and rotatable API keys; rate limiting; planned institutional SSO integration |
| 🗄️ **Databases & Storage** | PostgreSQL; SQLAlchemy; Alembic migrations; Qdrant vector database; Redis caching and session storage; MinIO S3-compatible object storage |
| 🔄 **CI/CD & Testing** | GitHub Actions; backend unit and integration tests with pytest against real PostgreSQL, Redis, and Qdrant containers; frontend tests with Vitest, Testing Library, and MSW; Playwright end-to-end tests on desktop and mobile viewports; Ruff, Pyright, import-linter, ESLint, and TypeScript checks; pull request checks; branch protection |
| 📊 **Observability** | OpenTelemetry instrumentation; centralized structured logging; cross-machine log aggregation with Loki; distributed tracing with Jaeger; Grafana dashboards; service monitoring |
| 📐 **Documentation & Design** | Software Design Document covering system architecture, web client design, design decisions, interface design, infrastructure, risks, and development roadmap; separate frontend architecture, UX, and roadmap docs |
| **What I'm working toward:** | Collaborating with LCS to expand on the application and explore potential integration with WLU's academic advising and authentication systems. Institutional integration remains a future goal. |
